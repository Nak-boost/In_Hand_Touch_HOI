# 空闲 GPU 自动实验队列

2026-10-15 更新：下述 GPU 2、3 的旧计划因源代码已变更且尚无任务启动，已停止等待。当前采用 [桌面新抓取与 GPU 0、3 队列](tabletop_actual_queue.md)。以下保留旧计划记录。

`scripts/auto_manip_queue.py` 持续查询 GPU，资源合格后运行计划中的命令。当前启用的计划是项目根目录下 `research/compact_training_20261015/plan.json`，实时状态在同目录 `queue_status.json`。该计划使用已确认的 27 形状 compact 模型、校准后的奖励，包含球55/65、方块45/55、胶囊70/80六组掌心朝上 +Z 单物体教师实验。

## 当前资源策略

- 只使用物理 GPU 2、3，每张卡最多一组；每组 512 并行环境，1000 万环境步，seed=42。
- 每 5 秒检查一次，连续三次满足显存已用 ≤1024 MiB、空闲 ≥12000 MiB、GPU 利用率 ≤10% 才启动。
- “利用率为零但显存被占用”不满足空闲条件。每个流水线阶段前都会重新检查资源。
- 不终止其他进程，不分配虚假张量占位。文件锁只协调同一主机上使用该脚本的队列，不能阻止其他用户绕开队列提交任务。
- 512 环境是基于前次 27 体、256 环境约 2.8 GiB 资源测试的保守起点。当前 GPU 被占用，尚无本批 512 环境的实测训练峰值；每阶段的整卡显存采样峰值会写入状态。该统计包含其他进程可能产生的占用，不是精确的单进程显存。

## 自动执行顺序

每组独立执行生成抓取 → 30 秒保持/四指回撤诊断 → 缓存审计 → 教师训练。

1. 使用新模型生成 128 个候选，128 并行搜索环境，最多 40 批。缓存采用新文件名，拒绝覆盖。
2. 逐个检查30秒不触发失败，至少两处真实胶面—物体接触的帧占比≥90%，非胶面接触≤10%，贴近限位的关节≤2个。单指回撤是诊断项，不是硬门槛。
3. 至少16个合格且互不重复的抓取才进入训练；检查模型、碰撞、原始候选及质量报告哈希，关节顺序、尺寸、状态/目标有限性和限位，且实际训练缓存必须逐行对应质量报告选出的候选。旧85体缓存不会冒充新模型缓存。
4. 训练使用偏轴/超速平滑上限0.5/0.25、姿态系数0.05、失败代价250、无效限位指令系数0.25。训练配置显式固定这些值。

任何阶段非零退出或审计失败，该组标记failed，不自动进入后续阶段；队列继续其他实验。源代码和配置哈希在启动每阶段前复核，防止排队期间改动奖励或物理实现后悄悄改变实验。若确实修改了实现，应审查后生成新计划，而不是直接改写旧计划的哈希。

## 使用

当前队列已在后台启动，不要重复启动同一计划。只读检查：

```bash
scripts/python_manip.sh scripts/auto_manip_queue.py \
  --plan ../research/compact_training_20261015/plan.json --once
```

对于另一个尚未启动的计划，省略 `--once` 即运行。可通过 `--gpus 2,3` 指定范围，或显式 `--gpus all` 允许所有检测到的 GPU；本次实际队列没有使用all。

队列的PID写在 `queue_status.json` 的 `supervisor_pid` 和 `launch.json`。向这个PID发送SIGTERM可以停止队列及其自己启动的子任务；它不会按GPU编号杀其他任务。状态文件与日志保留，已有状态文件的计划不会自动重启，以避免重复训练；续排应新建计划目录并只列尚未完成的步骤。
