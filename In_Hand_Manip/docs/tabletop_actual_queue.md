# 新控制下的桌面抓取与 GPU 0、3 训练队列

日期：2026-10-15。

## 缓存

默认桌面配置已改用 `cache/digit_tabletop_box45_actual_checked_v3.pt`，包含 64 个独立初始状态及配对目标，手部保持 27 个碰撞形状。旧缓存与旧实验保留。

抓取生成通过 `tracking_action` 将预定的闭合轨迹转换为 [-1,1] 策略动作，并经过原有平滑、实际角增量、关节限位及 PD 控制；没有绕过新控制器直接施加理想位置。生成时要求真实胶面—物体接触，禁止非胶面支撑，限制接触力和线速度。

新缓存全部通过 30 秒有界目标跟踪检查：没有任务失败，至少两路真实胶面—物体接触和桌面支撑占比均满足 >=90%，非胶面支撑 <=10%，胶面力 <=2 N，无被过滤的碰撞对。单指回撤 0.06 rad 是独立诊断，不是所有抓取必须通过的条件；拇指测试存在 2/64 失败。零动作会释放预紧力，64 个均在零动作测试中失败，不能把该缓存称为零动作稳定抓取。

缓存、源候选、质量报告、实际模型、碰撞过滤、关节限位/顺序以及新奖励配置的审计已通过。完整数据位于 `../research/tabletop_regrasp_20261015/`（相对项目父目录）。

## 队列

计划：`/root/In_Hand_Reconstruction/research/tabletop_actual_queue_20261015/plan.json`。
状态：同目录 `queue_status.json`。监测脚本：`scripts/auto_manip_queue.py`。

- 仅物理 GPU 0、3，每卡最多一个本队列任务，总并发最多两个。
- 先等待资源，再进行 256 环境、16384 环境步的短程 PPO 资源探测。探测记录进程级显存，整卡计算利用率不冒充进程级统计。
- 三个正式实验：45 mm 方块、+Z、seed 42/43/44，每组 256 环境、1000 万环境步；采用新的实际角控制、距离奖励 0.1、两指奖励 0.05、姿态惩罚 0.05。
- 探测前要求可用显存 >=6144 MiB；探测后要求可用显存 >= `max(6144, max(4096, ceil(实测峰值*1.25))+2048)` MiB。
- GPU 利用率 <=15%，每 10 秒取样，连续三次合格并在拿到 GPU 锁后再次检查才启动。
- 允许显存部分被其他进程占用，只要剩余容量和低计算负载都满足上述条件。零利用率但显存几乎占满不合格。
- 资源探测失败则阻止后续训练；训练前再次校验抓取报告与代码、配置、模型和缓存哈希。读取资源失败时不启动任务。
- 不会因只剩显存就往同一 GPU 填多组。其他进程仍可能在启动后增加负载；监测不能提供显存或算力的独占保证。

## 管理

只读检查，不重复启动：

```bash
scripts/python_manip.sh scripts/auto_manip_queue.py \
  --plan ../research/tabletop_actual_queue_20261015/plan.json --once
```

`queue_status.json` 记录 supervisor_pid；向该 PID 发送 SIGTERM 将停止本队列及它启动的任务，不会终止其他 GPU 使用者。旧 GPU 2、3 计划的六组实验尚未运行，已标为取消，避免继续使用过期配置。未来若要恢复那些物体的实验，应根据新控制重新生成计划并验证对应抓取。

正式训练目录：`../runs/manip/tabletop_box45_actual_distance_seed{42,43,44}_20261015/`；资源探测位于队列目录的 `resource_probe/`，不能当作收敛策略。
