# 当前操作项目实现审计（2026-10-12）

本审计对照本地 HORA 上游提交 `410d95824dd28b198f6d6910cb4c09330a6303be`、
当前全部新增任务/训练/部署文件、URDF 生成器、有效配置和已有验证记录。
这是一份实现及假设审计，不是实物校准报告，也不是正式策略性能验收。

## 责任和范围

用户明确要求过：HORA 基础上适配 Allegro+DIGIT，参考 AnyRotate 的训练方式，
掌心朝上、两轴操作；后来明确收窄为 55 mm 单球体、+Z 轴。
这些授权不等于认可关闭自碰撞、假定 DIGIT 几何正确、以 binary 完整替代 AnyRotate，
或把能运行的训练框架称为可用的实物策略。

此前我把几项重大任务/物理假设作为初版工程简化直接实现了，没有在实施前充分说明。
后来在文档或答复里提及，并不能补足此前的说明。尤其在已知自碰撞关闭后仍启动长训练不妥。
原 `teacher_sphere55_z_v1` 训练已停止，其产物保留为旧碰撞配置实验，不作为新实验的恢复点。

## 逐项发现

| 项目 | 实际实现及来源 | 影响与处理 |
|---|---|---|
| **整手自碰撞关闭（重大、自行改动）** | 原新增任务 `create_actor(..., filter=1)` 使所有手部形状共享过滤位；HORA 原任务用 `-1` 保留资产过滤规则，不是这个全局关闭值。 | 可造成手指/DIGIT 互穿和不真实换指。本轮修复为逐部件排除，仅直接相邻关节和同一固定组件内部不碰撞；其他手部件保留碰撞。 |
| **DIGIT 不是实测模型（重大、自行近似）** | `configs/digit_mount.yaml`：外壳 16×20×27 mm、20 g，胶面 2×16×20 mm、2 g；安装位置与角度是工程设定。 | 会改变可达范围、摩擦接触、惯量和遮挡。没有装配 CAD/测量依据，不能称为已适配真实 Allegro+DIGIT；需真实模型校准。 |
| **改了原手的碰撞几何（重大、自行改动）** | `scripts/build_digit_asset.py` 将掌部碰撞盒从上游文件中的 10 mm 立方体改为 40.8×113×95 mm；把末节原来的 0.1 mm 球代理换为 18×18×26.7 mm / 42.3 mm 的盒体，并删除原指尖 link、安装 DIGIT 代理。 | 不是只添加传感器：支撑位置和碰撞空间均变了。方向上是补齐碰撞，但尺寸、形状和安装并未实物标定；本轮不会把这些估计改成另一些未测量值。 |
| **手部重力关闭（重大、沿用 HORA）** | 新任务 `AssetOptions.disable_gravity=True`；上游 `_create_hand_asset` 也如此。物体仍受 -9.81 m/s² 重力。 | 固定手腕不等于手指无重力。模型相当于忽略手指及新增传感器的重力负载；代码没有证明真实硬件有等价重力补偿。这不是本次新发明的设置，但适用性未经验证，应显式评估开启重力/真实补偿。 |
| **只做 binary 触觉（重大、自行降阶）** | 四胶面净接触力 >0.1 N，1 控制步延迟、2% 漏检。没有接触位置、力大小、接触面积或触觉图像。 | 不等于 AnyRotate 完整触觉方案（每指 binary+两接触角+合力）。阈值、延迟和漏检率未经真实 DIGIT 校准。此前已在用户追问后解释，初次实现仍应主动说明。 |
| **胶面净力不识别接触对象（本轮启用碰撞后的连带问题）** | Isaac Gym GPU 净接触力张量不提供接触对身份；其他手指碰到胶面也会给出 binary。 | 这是传感器会实际感到的触碰，不应伪装成只有物体接触。抓取筛选改用物体—胶面真实接触对；策略观测保持净触觉语义。现有接触奖励仍是“至少两胶面受触碰”，不能称为“至少两指夹住物体”；它存在自接触奖励捷径，需后续奖励消融/约束。 |
| **固定手腕和原地起始抓取（任务边界）** | 固定手根在世界 z=0.5 m，掌心朝上；不学习机械臂动作或从桌面抓取。物体从缓存直接放入手中。 | “手内旋转”并不包含完整拾取过程。掌心朝上是用户偏好；固定手腕与缓存起始是所采用 HORA 范式的边界，应明确说明。 |
| **转一圈被替换为按时换轴（重大、自行任务近似）** | 原两轴配置每 160 步、8 秒切换，速度目标 0.5 rad/s；无物体姿态闭环到达/停止控制。现在按用户最新要求改为单 Z 轴，不切换。 | 8 秒按目标速度只对应约 229°，不是一圈；累计投影角也不等于精确终点姿态。后续恢复两轴时仍需明确精确圈数/目标姿态任务。 |
| **物体集和泛化范围收窄（重大、自行初版范围）** | 原来只有 sphere55、box50、capsule70 三个程序化刚体，非 ABC/AnyRotate 数据集；无尺寸随机化。现单球体是用户明确要求。 | 不能据此宣称形状或尺寸泛化。原清单每形状只有一个尺寸，形状和尺寸混杂。 |
| **奖励为自定义组合（重大、非论文原样复现）** | `post_physics_step` 新增偏轴、超速、30°里程碑、胶面/外壳接触、位移、动作平滑、掉落等；未照搬 HORA 的功率/姿态正则，也非 AnyRotate 完整 keypoint 奖励/重力课程。 | 系数未经收敛训练或消融验证。允许手掌/指节支撑、没有触觉覆盖奖励、没有抑制自接触的专门奖励；不能把它称为 AnyRotate 奖励复现。 |
| **失败和成功判定是工程阈值（自行设定）** | 物体 z<0.53 m 或距初始位置>0.13 m 才判失败；单回合 30 s。评估统计回合未失败且每轴累计有符号投影角≥2π。 | 可以容许较大漂移，未要求始终由指尖支撑、保持足够接触、或精确停止。评估也不验证表面覆盖和重建收益。 |
| **教师能力与学生可观测性存在差距（方法选择）** | 教师 23 维特权信息含真实物体四元数、线/角速度、物理参数、累计角度/目标；学生只有 71 维本体/binary/轴指令和历史。 | 相比原 HORA 的物理特权变量增加了状态信息，蒸馏更依赖可观测性。特别是对称球体的绝对朝向无法仅由四个 binary 唯一确定；能训练教师不保证学生能复现。未发现学生直接读取特权真值的路径，已有隔离测试。 |
| **训练结构/超参数不是直接继承全部默认值** | PPO 核心来自 HORA；教师 MLP 改为 256/256/128，特权 MLP 128/64/8；学生新写 TCN+actor 联合蒸馏，学生执行、教师提供标签。学生不是 PPO。 | 属 AnyRotate-inspired 实现，非官方复现；学习率、批量、步数和网络大小都是工程选择。教师默认从头训练，不是已有 HORA 权重迁移。 |
| **控制、摩擦、质量也是假设** | 20 Hz 策略/120 Hz PD、Kp=3/Kd=0.1 源于 HORA 设置；动作步幅0.026 rad和平滑0.5自行设置。实际 URDF 力矩上限0.35 Nm（代码上界0.5不会把它升到0.5）。质量30–120 g，摩擦0.6–1.5、COM±3 mm、PD倍率0.9–1.1。 | 没有硬件辨识。胶面、外壳、指节和物体使用同一个环境摩擦系数，没有区分材质；参数随机化不等于已覆盖真实误差。 |
| **HORA 配置有继承但不生效的字段（易误用）** | `manip.yaml` 继承原 task，仍能看见 `randomization.randomizeScale`、`forceScale`、原 reward 等；新任务仅读取自己的 `objects/domain/manipulation`，未实现上游随机外力逻辑。 | 用户修改旧字段可能不改变新任务。README 明确新配置位置；需后续整理配置/拒绝不支持的覆盖，避免“配置里写了即已实现”的误解。 |
| **抓取样本少且并非动态操作验证** | 初版每物体64个，筛选固定关节目标下约4秒，允许一定物体速度；无长期稳定、全动作可达性或两轴可操作性保证。 | 静态缓存成功不是旋转成功。碰撞改变后必须重新生成；本轮加入碰撞签名、真实物体接触对筛选，旧缓存拒绝加载。 |
| **初始抓取条件未复现 AnyRotate（重大范围差异）** | 当前≥2个胶面接触、单重力方向、允许掌部/指节参与支撑；AnyRotate论文为>2个指尖接触、非指尖接触为0、六向重力筛选、每物体10,000个。 | 当前是宽松的静态抓取基线，不能当作AnyRotate的precision grasp初始化复现。canonical_q也是我自行选定的工程姿态。详细对照见 `docs/initial_grasps.md`。 |
| **真实部署没有实现（重大范围缺口）** | `DigitPolicyRuntime` 只是张量→关节目标适配器，无 Allegro 驱动、DIGIT采集、时间同步或真实触觉观察器；`scripts/deploy.sh` 仍是上游入口。 | 不能称为已完成实物部署。用户 IDE 中 `train_s1.sh/vis_s1.sh/eval_s1.sh/deploy.sh` 都可能指向原 HORA；新项目必须使用 `run_manip.sh`，避免跑错任务。 |
| **重建和闭环尚未接入（整体项目阶段）** | 无 TACTO、触觉深度/点云观察器、位姿形状估计、覆盖度反馈；未修改 TouchFM 算法来实现融合。 | 操作基线不等于完整纯触觉重建系统，也不等于 NeuralFeels 复现。 |
| **验证范围被过度概括的风险** | 原“5项测试、GPU仿真、短教师→学生→评估链路通过”均只证明可执行。 | 尚无收敛、泛化、实物、接触几何精度、长期稳定旋转结果。本次报告明确区分运行验证和任务成功。 |

## 本轮实际修复范围

1. 停止旧正式训练，保留日志和权重以便追溯。
2. 修复手部碰撞掩码：25 个刚体、28 对连接/固定装配排除，其余不同刚体对启用碰撞；物体与所有手部形状仍可碰撞。
3. 在实际创建的 actor 上检查过滤位，避免配置正确但创建时被覆盖。
4. 缓存、教师/学生权重和运行元数据增加碰撞签名，禁止无碰撞实验静默续接。
5. 抓取筛选读取真实物体—胶面接触对，避免手指自接触混淆。
6. 新增掩码全矩阵测试、旧数据拒绝测试和 PhysX 开/关碰撞行为对照脚本。

其他重要物理/方法假设保留并在上表明示，未把整个项目声称为校准完成。尤其手部重力、
DIGIT真实几何、净触觉奖励语义和真实部署仍需要后续处理。

验证结果：7项测试通过；PhysX开启/关闭对照分别出现79/0种手部接触对，排除对为0；
重新生成64个真实物体—胶面接触的抓取；缓存随机抽样64次、GPU零动作保持5秒，63次未触发失败。
短教师PPO→学生蒸馏→评估链路通过，短评估转满一圈成功率仍为0。
完整证据见 `docs/validation.md` 和 `docs/collision_validation/`。
