# 胶面—目标物体接触筛选：实现和测试

日期：2026-10-16。代码位置：`../../In_Hand_Manip`。测试 GPU：物理 GPU 3。

## 实现范围

新增 `task.env.manipulation.object_contact_filter`，默认 `false`；旧配置缺少该字段也关闭。
开启后，每个控制步只查询一次每个环境的接触列表，筛选胶面刚体与目标物体刚体的接触，
每个胶面的正法向载荷相加后与现有 0.10 N 阈值比较。奖励和失败条件共用这份布尔掩码。

- 至少两个胶面有效接触物体才获得原有接触奖励。
- 桌面任务只有有效物体接触才能清零失触计时；连续无接触 2 秒仍按原配置扣 250 并重置。
- 非桌面任务原本不以失触作为失败条件，所以该任务只改变接触奖励。
- teacher/student 输入仍是原始净力阈值触觉，保留延迟、漏检和历史，不屏蔽自接触。
- 未修改碰撞几何、物理过滤位、抓取缓存、其他奖励权重或动作控制。

这里是任务信号筛选，不是关闭物理接触。法向载荷与原先含剪切的总净力模长定义不同；
两者不能视为完全等价。接触来自控制周期最后一个物理步，不额外累计整个控制周期。

启用时在既有运行命令后追加：

```bash
pipeline=cpu task.env.manipulation.object_contact_filter=true
```

Isaac Gym Preview 4 无法在 GPU tensor pipeline 启动后调用 `get_env_rigid_contacts`。
因此必须显式使用 CPU tensor pipeline；`sim_device=cuda:0 rl_device=cuda:0` 仍使 PhysX 和 PPO
运行在 GPU。配置不兼容会立即报错，不会静默返回零接触或自动切换管线。
恢复原运行条件需要同时设置 `pipeline=gpu` 和开关 `false`。

## 正确性

`tests.log`：26 项测试通过，覆盖接触双方顺序、多个接触点求和、自接触/桌面/外壳剔除、
弱物体接触不能被强自接触抬过阈值、空接触、非法载荷、管线兼容和失触计时。

`verification.json`：对 256 环境 × 500 控制步的回放，逐步核对两种模式各自的接触奖励、
失触计时和失败代价。开启模式在自身轨迹上与“使用原始触觉”的反事实条件比较：
15,518 个环境步不再获得原先会获得的接触奖励；100,912 个环境步中，原始信号本会延长
存活、物体接触条件则判失败。所有策略观测仍按原始信号生成。

上述计数包含禁用重置后重复出现的失败帧，不代表独立失败次数或策略成功率。
独立 GPU PhysX 回放即使初始状态和动作相同也发生轨迹分歧，因此不把两次回放的奖励
逐帧相减归因于开关。进一步在完全相同物理状态、随机数状态和历史缓存下核对 `_observe`，
开关前后全部观测张量逐项相等，见 `paired_benchmark.json`。

另执行开启筛选的短程 PPO 集成测试：`manip_tabletop_box45`，256 环境，CPU tensor pipeline、
GPU PhysX/GPU PPO，`max_agent_steps=16384`、`minibatch_size=4096`、seed 215。
训练输出 `max steps achieved` 并正常退出（退出码 0），日志为 `ppo_smoke.log`，
运行产物在 `ppo_smoke/filter_on/`。此测试只验证训练链路，不验证策略收敛或旋转能力。

## 性能

计时同步 CUDA，只计 `env.step`，不包括 PPO 更新、初始化或验证数据导出。
每次 100 步预热；禁用自动重置但仍计算奖励和失败，避免终止条件主动改变重置序列。

最直接的筛选增量测试是同进程、同一连续物理轨迹上的 ABBA 交替开关：256 环境，
400 个计时步，每种模式 200 步，使用关节目标保持动作。

| CPU tensor pipeline | 每控制步平均耗时 | 环境步/秒 |
|---|---:|---:|
| 关闭筛选 | 58.09 ms | 4,407 |
| 开启筛选 | 68.30 ms | 3,748 |

筛选使每步耗时增加 **17.6%**、吞吐下降 **15.0%**。接触查询与聚合平均占 **9.48 ms**。
奖励和失败复用查询结果，因此同时筛选两者并不需要两倍接触查询开销。

为估计切换管线的整体影响，另以固定教师动作序列回放三种设置，每种独立运行三次，
每次 400 步计时，第二轮反转测试顺序：

| 模式 | 三次平均步耗时（ms） | 步耗时中位数（ms） | 对应环境步/秒 |
|---|---|---:|---:|
| GPU 管线，关闭 | 27.14 / 43.21 / 35.25 | 35.25 | 7,262 |
| CPU 管线，关闭 | 58.16 / 36.37 / 40.00 | 40.00 | 6,400 |
| CPU 管线，开启 | 43.22 / 58.09 / 55.39 | 55.39 | 4,622 |

中位数粗略比较：CPU 管线内开启后每步耗时增加 38.5%；相对原 GPU 管线基线，
每步耗时增加 57.1%，吞吐下降 36.4%。共享机器负载和独立物理轨迹差异导致波动较大，
这些数字只作整体开销参考；筛选本身的增量优先参考上述同进程 ABBA 测试。
两类测试的动作和轨迹不同，不能直接合并各项耗时。

进程显存采样峰值：GPU 管线关闭约 2,756 MiB；CPU 管线关闭和开启均约 1,916–1,980 MiB。
本次没有观察到筛选带来大幅显存增加，代价主要在主机查询、遍历环境及数据管线。
这是 256 环境结果，不能直接代表数千环境的完整训练吞吐；每环境一次 Python/API 查询
会随环境数增加，正式扩大规模前应先测目标规模。
