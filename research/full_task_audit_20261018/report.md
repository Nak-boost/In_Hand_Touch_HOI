# 悬空与桌面任务联合审计

2026-10-18。针对“拇指模型是否还有其他未说明错误”的扩大检查。审计覆盖当前工作区、三个运行进程的冻结代码/完整配置、手部资产及网格、缓存来源、控制/观测/奖励/终止、PPO、学生接口和回放。**这次没有更换训练资产、缓存、网络、奖励或控制，也没有重启正式训练。** 新增文件都在本审计目录；此前拇指修正文件和其他会话的工作保留。

结论：当前两类任务的 27 形状模型没有查出另一处类似拇指根部翻转的明确装配错误；但项目并非没有其他问题。发现了悬空网络配置与此前“只借用训练参数”的约束不一致、最佳检查点选择缺陷、旧抓取验证脚本与新控制方式不兼容，并验证了桌面球体初始化在新随机参数下的触觉阈值失效。必须区分代码缺陷、已有简化、训练目标差异和未验证的硬件假设。

## 确认的问题与影响

### 1. 拇指翻转：当前仅该处显示错误，历史 85 形状包含物理错误

沿用前一轮逐元素/FK/厂商网格核对证据，见 ../thumb_geometry_audit_20261018/report.md：

- 当前三个运行资产 SHA256 相同，均为 compact_inward90，thumb link_12 的 visual 多了 Rx(pi)；碰撞仍为未翻转的厂商盒。
- 当前原手部 16 个主动关节运动学、角度限制、原 17 个 link 惯量与 HORA 实际 internal 模型一致；原手部 visual origin 唯一异常是上述根部。
- 历史 85 形状把 visual 变换复制到根部三个碰撞凸包，物理也错。该版本的旧结果不能作为正确真实装配的证据。
- 隔离的 thumb_visual_fixed 资产已存在，但**当前三个训练进程仍用原文件**。没有绕过资产/缓存/检查点哈希去替换。
- 旧构建链仍从 allegro.urdf 出发，可重新产生错误。未来重建应先修正构建基准，不能只修一份输出文件。

当前 27 形状不是完全照抄官方 URDF：掌部 3 凸包，指节 12 个厂商盒＋4 个末节单凸包，DIGIT 4 外壳＋4 胶面。食指 -90°、无名指 +90°，中指/拇指 0°；两任务使用同一局部安装，只整体手姿态不同。

### 2. 悬空网络配置差异需要纠正说明

来源是 In_Hand_Manip/configs/manip_hora16384_sphere55.yaml:9，six_objects 经 gel_rotation 配置继承它。不是显示或日志误报：运行的 resolved config 就是大网络。桌面的两个完整配置已保留小网络。

此前 gel_rotation_pair_20261017/report.md 也记录大网络，但“旧报告写过”不能证明用户批准。**就本对话“只挪用训练配置，不挪用网络”的约束，不能声称悬空版本也满足。** 本次没有改变已训练网络；更换会涉及权重结构和新实验，不能作为审计小修静默完成。

### 3. PPO 会在没有完成回合时保存默认 0 分的 best

hora/utils/misc.py:70 的 AverageScalarMeter 初始 current_size=0、mean=0；hora/algo/ppo/ppo.py:193–207 没检查 meter 是否为空就比较 best_rewards。save_best_after=0，初始 best=-10000，因而尚无完整回合也可能保存“best=0”；如果随后真实回报一直为负，该检查点可能长期保留。static_checks.py 已复现这一条件。

这影响模型选择/指标可信度，不直接改变 PPO 优化梯度，不能认定是旋转学不会的根因。本次读到悬空 best 已是有训练进度的正回报权重，不能把所有 best 都判为无效。桌面续训目录也不保证已产生新的 best，旧 best 阈值会从检查点继承。

另外，ppo.py:182 的累计 FPS 用恢复后的总步数除以本次进程耗时，续训后会高估；Last FPS 按本轮 batch 计算，解释吞吐应使用后者。

### 4. 旧版回撤验证工具不适用于 actual_position

scripts/check_grasp_cache.py:76–84 先改 env.targets，再调用 step(零动作)。当前 pre_physics_step 又按 q_actual + scale × action 重算目标，因此设置的回撤目标被覆盖。单独复现：把 previous_targets 减去 .08 rad，在 actual_position＋零增量下输出目标完全相同。

这意味着该脚本不能继续被用来证明当前控制方式下的回撤能力。**没有据此判定当前缓存全错**：桌面来自 evaluate_tabletop_grasps.py 的 tracking_action 验证；悬空来自 prepare_grasps.py / merge_validate.py 等有界跟踪流程。八个物体库的验证报告哈希、数据源、关节顺序、角度范围、姿态四元数和控制模式都已核对。

### 5. 桌面球体“轻接触”不保证跨随机参数达到 0.1 N 阈值

新增独立场景：seed=901，重新采样质量/质心/控制增益，跟踪缓存目标 80 个控制步（约 4 秒），关闭自动重置以记录第一回合：

| 场景 | 起始数 | 触发任务失败的状态数 | 平均至少两路有效胶面接触占比 |
|---|---:|---:|---:|
| 悬空六物体，合计 | 12 | 0 | 91.98% |
| 桌面球体 | 16 | **3** | 76.48% |
| 桌面方块 | 16 | 0 | 100% |

球体失败发生在第 45/47/48 步，均为 contact_lost=true、outside_workspace=false。球仍在桌面中心附近 z≈0.5275 m；失败时仍有 0.009–0.056 N 的物理接触，却全部低于 0.1 N 有效阈值。目标增量损失约 1e-8，并非限位裁剪导致。它们是“有效触觉持续不足”，不是物体掉落或完全没有物理接触。

因此缓存的固定 seed 验证不代表对所有质量/增益都稳定。适合下一步核对轻接触预载裕度和真实 DIGIT 接触阈值，再决定是否重新筛缓存；不能仅为通过测试随意降低阈值。这是小样本诊断，不是精确失败率估计，也不是训练策略评估。

已有悬空混合缓存复验也有同类泛化边界：新随机参数每物体 64 次，box45 接触质量通过 48/64、box55 52/64，sphere55 62/64、sphere65 62/64、capsule70 60/64、capsule80 64/64。脚本采用的是集合验收门槛，并非所有状态都通过。此次重新核对来源，没有重新宣称这些是本次新跑的 30 秒实验。

## 已有设计/近似，不能误称为“只是显示”

1. **桌面 shared filter 改变物理碰撞。** 四胶面和桌面共用屏蔽位，取消胶面—桌面，也取消胶面—胶面碰撞。这是用户此前明确接受的简化。外壳—桌面、胶面—物体和其他未排除手部对仍允许碰撞；不能说所有手部自碰撞都取消，也不能说只屏蔽读数。
2. **触觉输入与奖励触觉不同。** Actor 仍用每胶面净合力阈值的 binary，含物理允许的自接触、2% dropout 和 1 控制步延迟。奖励/桌面失触用胶面—目标物体正法向载荷的和。独立逐接触复算与读数最大误差 <6e-8 N，未发现把外壳/掌部/桌面当物体胶面奖励的索引错误。
3. **胶面是刚性碰撞网格实体。** 不是零厚度单面检测器，也没有 DIGIT 图像、弹性形变仿真。当前筛选只看 body 身份和正法向载荷，不进一步验证接触点是否在光学有效正面；“真实物体接触”不等于已证明真实图像可观测性。
4. **手部所有 link 禁用重力，物体保留重力。** 固定根部不等于必须取消指节重力；这是控制/仿真近似。DIGIT 采用名义 20 g、均匀密度包络近似惯量，未做实机标定。关节 effort 继承 HORA 的 .35 N·m，代码另设上限 .5，当前实际仍 .35；不是厂商 URDF 的 15。
5. **零动作不等于保持旧抓取目标。** 两类任务都是 q_target=clip(q_actual+.026×平滑动作)，alpha=.5；显式 PD，控制约 20 Hz、物理/PD 约 120 Hz，kp=3、kd=.1。没有 TACTO。零动作让历史动作逐步衰减，移除持续预载。缓存要靠有界动作跟踪保持，不能套用旧 previous_target 的零动作测试。
6. **悬空与桌面失败条件不同。** 悬空：z<.53 m、相对初始位置偏移>.13 m 或状态非有限；没有连续失触失败。桌面：xy 半径>.1 m 或有效接触全无持续 2 秒；不以高度/倾倒失败，数值非有限单独报错。桌面两秒内恢复任意一路 >.1 N 就清零计时。失败扣 250。
7. **奖励门控并不涵盖所有进展奖励。** 悬空正向连续旋转项乘 [0.1,.5,1]，逆向惩罚不缩减；goal_weight=.25 的离散过角度奖励仍没有接触门控。桌面连续旋转项也没有门控。至少两路有效胶面奖励 .05；靠近物体是胶面参考点到物体中心距离，不是表面距离/法线对齐/力闭合。靠近、保持接触和保持姿态都不保证学会换指。
8. **网络接口。** Teacher 71 维当前帧＋23 维特权量编码；Student 30 帧历史 TCN。当前帧含 q/qdot/上一目标/上一平滑动作/4 触觉/轴指令；23 维特权包含位姿速度、尺寸/质量/摩擦/COM/目标进度，没有稠密形状或显式手—物体几何。Student 实现主动丢弃 priv_info，未发现特权输入泄漏。
9. **学生实机接口尚不是完整硬件部署。** DigitPolicyRuntime 与仿真共用目标变换，但初始目标取 q；仿真缓存可有预载目标，且初始触觉清零。真实调用方还须保证关节顺序、触觉标定/时延、控制频率与低层控制一致；不能据接口可运行宣称已完成实机验证。
10. **可复现保护仍有边界。** 当前资产/碰撞签名、网格清单、缓存对象列表/关节顺序能检出多种错配；缓存加载器不强制检查所有 quality_validation 元数据，teacher 恢复也不核对完整奖励/控制参数签名。回放通常依赖保存的完整配置和源文件检查，源检查列表不是全依赖覆盖。此次实际源文件核对未发现当前三组读取了错误快照。

## 本次执行的验证

- `scripts/python_manip.sh -m pytest -q tests`：**99 passed in 40.03s**。这是现有代码测试通过，不是所有物理假设已正确的证明。
- inventory.py / static_checks.py：三组 frozen、run/source、workspace 对比；资产/全部 manifest 保护网格哈希；碰撞掩码逐对真值表；8 个缓存分组的有限性/关节限位/四元数/来源哈希；复现空 meter best 与旧回撤失效。
- geometry_sweep.py：**467 姿态**。42 标准插值、169 拇指网格、128 随机、8×16 缓存抽样。前两类及缓存抽样无 >.1 mm 的启用碰撞对穿插；随机姿态有 63 个含穿插，随机合法关节角不等于物理可达，不据此断言模型错误。对出现穿插的 pair，用修正 thumb 根部朝向后的 CAD 凸包包络作单侧参考，没有发现“模型穿插但参考包络分离”的新案例。参考包络相交不能反过来证明真实 CAD 一定碰撞。DIGIT 沿用其当前刚性代理，未独立标定胶面。
- probe.py：GPU1 独立小场景，逐组加载各自冻结源码；悬空 12 环境、桌面各16，每组跟踪80步＋小随机动作80步。有限状态/奖励、奖励分项求和、奖励接触数、手/物体 body 身份、被屏蔽 pair 不产生正接触力均通过。桌面还验证了两秒失触边界及恢复触觉计时清零。三个独立仿真均正常 close，退出码0。
- 随机小动作仅用于接口检查，桌面球10/16、方16/16会失效，不能当作已训练策略表现。关闭自动重置的诊断会在失效后继续观测，因此 probe JSON 的整段 mean_reward 可能重复计入失败扣分，**不用于训练回报比较**。
- 接触读取 wall time 在这次小场景约 .6–1.1 ms/控制步；不是16384环境吞吐基准，不能线性外推。已有训练记录的 process_time 是进程CPU时间，可能包含其他原生线程工作，不等同独占查询线程周期数。

几何、独立接触复算、控制和失败逻辑通过，不证明之前 SIGSEGV 已解决，也不证明长时16384环境稳定；本次没有做原生崩溃复现或根因定位。没有执行真实硬件试验、未遍历所有可达姿态/接触轨迹、没有重训或评价当前学生泛化。

## 建议处理顺序

1. 修正构建基准及可视化资产的迁移流程；85形状历史资产明确隔离，不沿用其物理正确性结论。
2. 明确悬空网络是否恢复原项目尺寸；保持正在训练的历史证据，不在原实验中途静默换结构。
3. 修复空回合 best 与旧验证工具；这些属于可以独立验证的实现缺陷。
4. 对桌面球体做跨质量/增益的缓存预载与阈值裕度复验，明确“仍有接触但低于阈值”的失效，而非笼统归因于掉落/饱和。
5. 再单独比较接触门控、无进展/失触处理等训练目标；这些属于新实验设计，不混入几何修正对照。
