# 2026-10-14 显存复核

当前训练快照对比：旧 teacher_sphere55_z_self_collision_v1 为1024环境，新v2为256环境。
两者策略网络均为[256,256,128]，特权编码器均为[128,64,8]，horizon均为16；
minibatch从8192降到4096。自碰撞excluded_pairs完全相同。

URDF显式碰撞形状：旧25个、新85个，刚体link均为25个。
掌部从1个变为23个；指节从各1个变为各1–5个；胶面和外壳仍分别1个。
变化来自ed93077的碰撞几何更新，不能归因为本轮新启用自碰撞，也不能归因为网络变大。
更多凸体使单个刚体对可包含更多形状对；实际同时接触数和GPU内存开销尚未做同轨迹A/B测量。

新旧sim配置中max_gpu_contact_pairs均为8388608、default_buffer_size_multiplier均为5.0、
contact_collection均为2。这些容量配置没有跟环境数同步缩小；本身不是新旧差异，
但不能据256/1024比例推断显存也下降到四分之一。

v1 sphere65以及v2 sphere65/box55均有PhysX内存分配失败日志。
v2 sphere65第244–245行先请求545259520与2181038080字节失败，再报内部CUDA错误。
v2 box55第632行起同样出现多次分配失败；v2 sphere55以-11退出，不能仅凭退出码归因为显存。
这些日志确认物理引擎内存压力，但尚不能证明不存在PhysX泄漏或接触规模异常。

复核时GPU1的box45进程为11716 MiB、capsule70为7924 MiB，均为256环境；
上轮首启合计约7.1GB不能代表长程峰值。256环境方案并未解决长期显存增长问题。

后续定位应在隔离的小规模回放中同时记录NVML进程显存、torch allocated/reserved、
实际接触/约束规模，并对固定保持和随机/策略动作、旧/新碰撞几何作控制比较。
再决定是否合并冗余凸体或调整缓冲容量。不能用关闭手部自碰撞代替定位，
也不能直接认定10GB是新模型必然且合理的需求。

本轮为只读配置与日志诊断，未修改物理模型、奖励或现有训练进程。
