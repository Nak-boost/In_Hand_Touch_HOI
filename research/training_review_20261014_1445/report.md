数据快照：2026-10-14 14:46（北京时间）。仅新增分析文件；未修改训练代码、配置、物理模型或进程。读取六组 v2_env256 的 TensorBoard、控制台、best/last 检查点，并核对奖励和日志实现。

## 结论

尚无稳定持续绕 +Z 旋转的证据。sphere55、box45 出现正向角速度增长，但回合显著缩短、非目标轴运动较大；box55、capsule70 出现严重目标限位饱和、低转速和弱胶面接触。与此同时，四组进程异常退出，不能把这批结果当作正常完成的训练对比。

## 主要发现

1. sphere55 的回合奖励从最早 100 次更新的约 -522 改善到 -79，但回合时长从 6.07 秒下降至 1.29 秒；box45 奖励约 -876 → -190，回合时长 15.39 → 2.36 秒。前者转速接近目标不等于稳定旋转，后者仍明显不足。两者都呈现频繁提前结束而非持续持物的迹象。没有完整一圈成功率记录，不能断言已经转完一圈。
2. 非目标轴角速度平方均值：sphere55=18.35、box45=17.47，对应 RMS 约 4.28、4.18 rad/s，远高于目标轴有符号均值。RMS 与有符号均值不是同一统计量，但足以说明伴随明显非目标轴运动，不能将所有运动解释为受控绕 Z 旋转。可能包含失稳/脱离后的运动，需轨迹回放定位。
3. 当前奖励存在需要优先验证的提前终止激励：每步旋转奖励最高 +1；sphere55、box45 的非目标轴惩罚均值分别约 -2.75、-2.62，姿态惩罚分别约 -0.28、-1.01，另有其他负项。掉落/位移失败只一次扣 5 分。在持续负回报下，提前失败可能比持续运行获得更高回报。这与回合变短、总奖励提高的现象一致，但尚不能断言策略已学会主动丢物；需受控回放和奖励拆解对照。
4. box55 有 71.6% 的 PD 目标贴近关节边界，82.3% 的请求增量被裁掉；capsule70（首次内存错误前）分别为 80.1%、83.3%。这是关节目标饱和，不是 PPO 动作均值边界惩罚的同一个概念。对称边界损失已启用，但不能自动解决累积 PD 目标不断撞限位的问题。
5. 加入初始关节姿态惩罚没有消除该退化。它惩罚实际 q 偏离初始 q，不直接惩罚 PD 目标贴边，也不能保证胶面接触或物体保持。球55姿态惩罚降低还可能部分来自更频繁 reset，不能单独解释为抓取改善。
6. 方块55胶面触发数仅 0.03，方块45为 0.22，胶囊70约 0.30；胶囊70外壳触发数约 2.00。说明策略没有持续利用足够的胶面接触，胶囊组可能依赖外壳支撑或手部自接触。日志来自刚体净接触力阈值，并非逐对的物体—胶面接触检测，无法仅凭这些数确定具体接触对象。胶面触发低也不能判断一定掉落，物体可能由其他部位支撑。
7. best.pth 选取依据是回合总奖励。sphere65 的 best 来自第1次更新，box55 第6次，capsule70 第8次，几乎是启动阶段，不能作为“训练后的最佳旋转策略”。sphere55 best 是第607次更新，box45 第1044次。读取到的模型权重均有限，但这不证明物理仿真有效或策略成功。

## 运行可靠性

- sphere65、box55、capsule70 都有 PhysX GPU 内存分配失败，随后出现 CUDA illegal memory access。
- capsule70 在约 361 万步已经第一次分配失败，直到约430万步才退出；首次错误后的统计不用于主要判断。
- sphere55 exit -11，尚无直接日志证据确认是内存耗尽，不能与另三组完全同因归类。
- 分析期间（14:45）capsule70退出，原有队列自动启动capsule80；不是本次分析手动启动。
- box45 最近100次更新墙钟吞吐约119步/秒，最初100次约1474步/秒，下降约12倍。sphere55约975→55步/秒。这里用事件时间差计算局部速度，不使用累计FPS替代近期速度。
- 14:44 GPU1约24GB占满；capsule70退出后，box45仍占约11.7GiB，刚启动的capsule80约4.0GiB。GPU2/3当时空闲，但队列固定GPU1。此次没有修改调度。
- 以上说明缩至256环境后仍未解决长时间运行稳定性；内存增长根因尚未隔离，不能仅凭这些数据断言是85个碰撞体必然导致或确定存在泄漏。

## 建议顺序

1. 优先解决并验证仿真长期稳定性，区分单进程增长和同卡并行挤占；GPU分散是资源缓解，不等同于根因修复。
2. 对现有 sphere55、box45、box55 检查点进行确定性回放，记录整回合角度、失效前后姿态、真实物体接触对、请求目标与实际关节位置。重点确认“短暂旋转后失稳”和“目标饱和后停转”各自发生在哪些阶段。
3. 在上述证据基础上，再设计奖励/控制对照，检查持续负回报和提前终止收益，以及实际q惩罚与目标限位之间的关系。不能只凭0.3系数或单条奖励曲线就擅自调大/调小姿态惩罚。
4. 后续 checkpoint 选择应结合持续持物时间、完整一圈成功率、目标轴净转角和非目标轴运动，不能只靠回合总奖励。当前每组一个seed且步数不同，尚不足以比较物体难度或泛化性能。

本次结论基于训练日志、检查点和代码，未额外运行仿真评估。
